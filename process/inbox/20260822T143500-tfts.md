# TFTS — 2026-08-22T14:35:00Z
problem:   Two independent totals engines produced different JSON for the same transaction data
fault_ref: none (discovered during math audit, not a runtime fault)
arc:
  - try:      Per-model compute_*_sell_cost_totals() functions (invoice_totals.py, order_totals.py, etc.) — each summed line.price.extended and preserved header-level tax/discount/shipping
    result:   failed — these functions did not compute tax from rates, did not handle line types (tax/shipping/discount lines), did not route adjustments. sell.total excluded line discounts while totals.total included header discount. Two different numbers for "total."
    revealed: The per-model functions were the original implementation. They treated tax, shipping, and discount as header-level preserved values — user enters them, system stores them. No computation.
  - try:      Generic recalculate_totals() in totals.py — handles all transaction types, computes per-line tax from finance.sales_tax_rate, routes line_type (tax/shipping/discount/product), builds tax audit trail
    result:   succeeded — one function, all models, computed values, proper line-type routing
    revealed: The generic engine was built later but never replaced the per-model functions. Both ran depending on code path. API saves called the old engine. Manage view called the new one. Same data, different totals JSON.
principle: |
  JSON is the source of truth — one engine computes it, all paths use that engine.
  Display values are projections of JSON, never inputs to it. Denormalized fields
  (total, balance on the header) are indexes into the JSON for query performance.
  They are NEVER authoritative.

  When you find two functions computing the same value, one is wrong. Consolidate
  immediately. The cost of parallel implementations is invisible until the values
  diverge, and by then the user has already made decisions on bad numbers.

  This applies to ALL models, not just transactions:
  - Item: price/cost/quantity JSON → denormalized on_hand, available
  - Serial: config JSON → display fields
  - BOM: cost_snapshot → parent cost.components
  - Transaction: totals JSON → total, balance DecimalFields

  Discipline: compute from data, display from computation, never the reverse.
