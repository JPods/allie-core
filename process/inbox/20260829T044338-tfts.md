principle: When a Django view returns 500, read the actual server error message before theorizing about the cause. A 500 on a POST could be auth, could be model, could be serialization — the status code doesn't tell you which. The fastest path is always: reproduce with curl, read the error body. In this case, `curl -s` returned `{"error": {"details": "'Document' object has no attribute 'model_name'"}}` — one command would have found the root cause immediately instead of investigating auth for an hour.

secondary principle: When writing serializer functions for Django models, never assume an attribute exists because the field name sounds like it should. `model_name` is a property on Django's Meta class, not a field on Document. The parent model name was stored in config JSON, not as a model attribute. Always verify field existence against the actual model definition.
