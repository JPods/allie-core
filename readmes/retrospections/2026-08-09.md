## Lessons for Allie

1. **config.actions[] replaces SerialLog** — Serial records are now self-contained. History travels with the unit on sync/export. SerialLog retained as read-only archive. This same pattern (embedded action arrays in config) could apply to other models where audit history needs to travel with the record.
   Domain tag: [WC3] [Cross-domain]

2. **Connection classes are the integration map** — 10 classes cover what a commerce platform needs day-one. The consolidated readme at `readmes/connections/connection-classes.md` is the canonical reference. Future classes (WMS, catalog sync, marketing, customs) are staged but not day-one.
   Domain tag: [WC3]

3. **Alice → Claude API is the learning bridge** — conn-ai-claude gives Alice a path to grow. She frames questions, Claude answers, she applies and learns. Each exchange makes the next one unnecessary. The supervision model (Claude converts first 2-3, Alice observes pattern, then handles simpler ones) is the right approach for pdfme reports.
   Domain tag: [WC3] [Cross-domain]

4. **Serial trends roll up to item-level Documents** — `Document(purpose=serial_trends')` consolidates defect rates, warranty patterns, inspection results across all serials for an item. Sequence numbers handle overflow. Alice monitors the trend documents, not individual serials.
   Domain tag: [WC3]

5. **Exact count match for serial shipping** — No partial. Selected serial count must equal line quantity. Auto-select by FIFO/LIFO/cost strategy handles the common case. Manual pick for exceptions.
   Domain tag: [WC3]

## Session 2 — Lessons for Allie

1. **Save pipeline is the highest-friction point** — Every field on every model must survive `full_clean()` + `setattr()` + `save()`. The six bugs we fixed (prefs blank, password blank, M2M fields, uuid comparison, non-model attributes, version conflicts) each independently blocked all saves. Alice's real-time compliance check at the save boundary prevents this class of bug before users hit it.
   Domain tag: [WC3]

2. **Schema compliance = Pydantic must inherit from BaseModel's default factories** — The source of truth is `default_metadata()`, `default_refs()`, `default_prefs()`, `default_comments()` in common/models.py. Pydantic schemas that don't inherit from the corresponding base class will reject valid records. The `depends_on: dict` vs `list` bug proved this — three schemas had the wrong type.
   Domain tag: [WC3]

3. **Alice's schema compliance is real-time coaching, not a batch job** — During data set setup, users hit validation walls multiple times a day. Alice intercepts at the save boundary, explains in user terms, offers to fix, coaches so they learn. Fix first, violation bucket for what she can't fix, never lose data.
   Domain tag: [WC3] [Cross-domain]

4. **One report dialog, used everywhere** — ReportsDialog.tsx is the single component for all report interactions. PrintReportDropdown is just the button that opens it. No duplicate dialogs.
   Domain tag: [WC3]

5. **Report script pipeline: before/during/after with unload and read_only** — When processing a group of records, script_before runs once, script_during runs per record (unload after each), script_after runs once. Records accessed read_only when not being changed. Built-in reports lock before/after, expose only during to users.
   Domain tag: [WC3]
