## Lessons for Allie

1. **vite build concurrency** — never run multiple vite builds simultaneously. Background task processes compete for esbuild and kill each other. Always `pgrep -la vite esbuild` before building. [Cross-domain]
2. **Date range as single source of truth** — one date range in db-header drives both the list AND the DD cards. Custom event (`wc3-date-range-changed`) decouples DataBrowser from DDCardDashboard. [WC3]
3. **WC2 QueryEditor JSON is the pattern** — four arrays (booleans, fields, operators, values) → JSON object. WC3 does the same as array of rule objects. Backend already handles all operators via `_parse_filters()`. [Cross-domain]
4. **Alice as search learner** — every complex search is a training signal. The intent text + the rules + the filters together teach Alice what users need. This is the observe→log→pattern→recommend loop applied to search. [WC3/Alice]

## Scars
- **Exit 144 build hell** — 6 failed builds because background processes stacked up. Cost: 30+ minutes. Prevention: always check for running vite/esbuild before launching a build.
