## Lessons for Allie

1. **Per-type quantity field names are a trap** — WC2's `qtyShipped`/`qtyOrdered`/`qtyReceived` made inheriting shared functions nearly impossible. WC3's `quantity.active` solves it: one key, document type gives meaning. Years of duplicated calculation paths in WC2 trace back to this naming decision. [Cross-domain]

2. **API-first beats local rate tables** — WC2 downloaded zone/weight charts and calculated shipping costs offline. The carriers change rates constantly; local tables go stale. WC3 asks the carrier's API directly. No tables to maintain. If the API is down, show "unavailable" — stale data is worse than no data. [Cross-domain]

3. **Connection records are the right home for carrier credentials** — not Settings. Carriers are external system integrations with credentials, rules, maps, and encryption needs. The Connection model was designed for exactly this. The sync domain owns external relationships. [WC3]

4. **Alice needs honest capability boundaries** — she runs on 8B/20B and should say when she can't handle something. The escalation protocol uses Action records with full context. The service is free — there is no subscription barrier. The cost of pretending is degraded output. The cost of escalating is one session delay. [Cross-domain]

5. **Packing is a process, not a quantity state** — there's no `packed` key in quantity. Packing organizes what goes in which box. The order→invoice conversion IS the ship event. The invoice line's `quantity.active` is the shipped quantity. Box contents live in `order.metadata.shipping.packed_lines[]`. [WC3]

## Lessons for Allie

1. **Reports are data, not code** — Every print template is a Report record with `config.form` JSON. No HTML files, no React components, no hardcoded layouts. Alice can draft them, users edit them in databrowser, WC_HQ can push fixes via UUID. The 400-line `reportLists.ts` is archived. One place to look: the Report model. [WC3]

2. **`model_name` collision is a class of bug** — When a table selector and a column share the same name (`model_name`), wcapi silently skips the filter. The fix (`model_name_filter` alias) is general — any future column that collides with a reserved param needs the same treatment. Watch for `id`, `status`, `name` collisions in custom queries. [WC3]

3. **Route params beat search params** — React Router's `useParams` returns the path segment, `useSearchParams` returns the query string. When both exist, path wins. If you update only the query string while the path stays the same, the component sees the old value. Navigate to the new path. [WC3]

4. **80/20 applies to maintenance, not just features** — High-usage reports self-police through user feedback. The risk is the 20% nobody uses — they break silently. Alice should weight review priority toward rarely-used, recently-modified, and new reports. This principle applies everywhere `times_used` is tracked. [Cross-domain]

5. **Canonical fields beat metadata** — `dt_approved`, `times_used`, `dt_last_used` belong on BaseModel, not in JSON metadata. They're queryable, indexable, sortable across every model. Metadata is for model-specific context. Universal concepts get universal fields. [Cross-domain]

6. **The user decides what to print** — No auto-detection of invoice type for print format. An invoice can mix positive and negative lines. The user picks "Invoice" or "Credit Memo" from the dropdown. Don't second-guess the user's intent from the data. [WC3]
