## Lessons for Allie

1. **"Post item ida" is the portable unit** — Bill clarified that cross-transaction flows copy item references, not prices or costs. The target transaction enforces its own rules. This is the same sovereignty principle applied to data flow: the receiving entity (transaction) decides how to value what it receives. Domain tag: [WC3] [Cross-domain]

2. **Lines are a verb, not a noun** — The column restriction isn't a limitation, it's a design decision. Too many columns and users manage spreadsheets instead of entering orders. The constraint serves the task. Same principle as JPods packet size → 1. Domain tag: [WC3]

3. **QQ is a clipboard, not a panel** — QuickQuote persists across transaction windows. It's the staging area between sell-side and exec-side. This maps to the MyCarryOn pattern: portable context that travels between contexts. Domain tag: [WC3] [Cross-domain]

4. **div show/hide beats separate windows** — WC2 needed separate windows because 4D couldn't show/hide panels. WC3 can query PostgreSQL on demand and render in place. The advantage isn't just UI — it's that panels share selection context with the grid. Domain tag: [WC3]

5. **Bill responds well to AskUserQuestion at decision points** — He explicitly praised the question interface for letting him steer without hitting escape. Use it at genuine decision points, not trivial ones. Domain tag: [Process]

## Session 2 — Statement Sorter: Client-Side Statement Classification Tool

## What Was Done

- **Fixed `alert()` blocking** — All 5 `alert()` calls and 1 `confirm()` replaced with non-blocking `toast()` messages. The alerts were freezing the page — user couldn't tell the page had loaded because a hidden dialog was waiting for dismissal.
- **Fixed `file://` protocol failure** — Chrome blocks `dataTransfer.files` reading on `file://` pages. Discovered via console error: "file: URLs are treated as unique security origins." Page must be served over HTTP. Started local `python3 -m http.server 8080` for testing.
- **Fixed folder drop** — Directory traversal via `webkitGetAsEntry` API. Original code tried entry API for all drops (hung silently on file:// for single files). Fixed to use `dataTransfer.files` for plain files, entry API only for directories. Added `readEntries` loop for >100 files. Added try/catch with toast error reporting.
- **Removed auto-load from localStorage** — Page always starts clean. No cross-session data leakage when served publicly.
- **Built WC list selection standard** — Click=select (clears others), Shift+click=range, Cmd/Ctrl+click=toggle individual. No checkboxes. Row is the selection target. Blue outline + highlight on selected rows. Selection count in toolbar. Documented at `webClerk3/readmes/topics/ui/list-selection-standard.md`. Saved to memory as team standard.
- **Fixed sticky header click-through** — Rows under the sticky header were receiving click events when toolbar buttons were pressed. Added `clientY < header.bottom` guard to `handleRowClick`.
- **Built grouped Business/Personal categories** — `BIZ_CATEGORIES` (22) and `PER_CATEGORIES` (13) with `<optgroup>` in all dropdowns. Picking a category auto-sets classification. `categoryClass()` function maps category → business/personal.
- **Built Edit Categories dialog** — Two text areas (business/personal), one per line. Apply, Cancel, Reset to Defaults. Save Categories / Load Categories (file picker). Always sorted alphabetically on apply/save/load.
- **Built merchant learning** — `learnMerchant()` called on every classification. Normalizes descriptions (strips dates, numbers, references). `recommendLine()` does exact match then substring match. Confidence based on match coverage + usage count.
- **Built recommendation columns** — `recommended` (yellow text) and `conf` (percentage) columns. Recommendations applied on file import for unclassified lines. Accept Recommendations button (orange) applies to all or selected rows.
- **Built Save/Load Rules** — `rules.json` = categories + merchants map. Save uses `showSaveFilePicker` for user-chosen location. Load restores categories, merchants, and applies recommendations to loaded lines.
- **Built A+- font sizing** — Buttons increase/decrease table font size (9-18px range). All table elements use `font-size:inherit`. Persists to localStorage.
- **Built draggable column widths** — Resize handle on right edge of each header. Drag to resize. Widths persist to localStorage via `ss_colwidths`.
- **Column reorder** — Decision columns centered: date → recommended → conf → category → class → amount → source → description → bank_cat. Eliminates eye-jump from left-justified description to right-side action columns.
- **Toolbar reorder** — Row 1: Select All, Clear Selection, A+-, Unload, drop zone. Row 2: Accept Recommendations, Edit Categories, Set Category, Show All, Sources, exports. Action above data.
- **Export includes all columns** — date, description, amount, source, classification, category, bank_category, raw. Exports use `showSaveFilePicker` for user-chosen save location.
- **Created `readme.md`** — Folder organization guide for users: year folders, categories.json placement, supported banks, privacy statement.

## Lessons for Allie

1. **`alert()` and `confirm()` are deployment landmines** — They block the entire page. On a server-hosted page, users can't tell the difference between "loading" and "alert dialog behind another window." Never use blocking dialogs in any WC tool. Toast messages only. Domain tag: [WC3] [Cross-domain]

2. **`file://` protocol is broken for drag-and-drop** — Chrome's security policy blocks file reading on `file://` pages. Any client-side tool that accepts file drops MUST be served over HTTP. This applies to all future standalone tools. Domain tag: [WC3]

3. **The row is the selection target, not the checkbox** — Bill: "As a general rule, our team should avoid selecting lists by clicking a tiny checkbox." Click=select, Shift=range, Cmd=toggle. This is now the WC standard for all list views. Standard browser behavior. Domain tag: [WC3] [Cross-domain]

4. **Decision columns belong in the center, not the right edge** — Left-justified description pushes action columns far right, forcing eye-jumps across the screen. Put decision columns (recommended, category, class) left of amount and description. The center of the screen is where the action is. Domain tag: [WC3] [Cross-domain]

5. **Category implies classification** — Don't make users set two fields when one determines the other. Picking "Groceries" from the Personal group sets both category and classification. Less is more. This principle applies to all WC forms: if a field's value is determined by another field, set it automatically. Domain tag: [WC3]

6. **Tools above where they are applied** — Toolbar row ordering matters. Action buttons should sit directly above the data columns they affect. Accept Recommendations above the recommended column. Set Category above the category column. Spatial proximity reduces cognitive load. Domain tag: [WC3] [Cross-domain]

7. **Merchant memory is the upgrade path to WebClerk** — The free tool learns merchants. rules.json carries that learning year to year. Users experience the value of classification memory → realize the full platform (Alice) does this automatically across all transactions. Free tool → paying customer. Domain tag: [WC3] [Commercial]

8. **db.list standard behaviors** — All WC list views should default to: row-click selection (no checkboxes), A+- font sizing, draggable column widths, column reorder to avoid left-justified gaps, tools above data, category-drives-classification, user preferences in localStorage. This is the reference implementation. Domain tag: [WC3] [Cross-domain]
