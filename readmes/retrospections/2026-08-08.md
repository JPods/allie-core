## Session 3 — WC2 Tally Salvage & Transaction Architecture

## What Was Done

- **WC2 tally architecture salvage** — read 15+ WC2 4D methods (calcOrder, calcInvoice, calcPO, calcProposal, OrdLnExtend, IvcLnExtend, CM_LineCalc, Ledger_TallyBal, GL_JrnlSummary, ConsolidateRecs, ItemSiteTally, DealLoc_Tally, ShippingCost, TaxCalcLine, Get_Price, BOM_ExtendCost). Identified three-layer tally architecture: line extension → header rollup → cross-document consolidation. Plus TallyMaster as a script engine.

- **Report model — 3 script fields** — added `script_before`, `script_during`, `script_after` TextFields to Report model. Added `tally` and `dashboard` to REPORT_CATEGORY_CHOICES. TallyMaster concept carried forward as Report records, not Settings. Migration 0034 applied. Bill's decision: three phases because built-in reports can lock before/after and only expose "during" to users.

- **Address verification supervisor** — replaced stub in `apps/sync/services/address_verification.py`. Three-tier: (1) Carrier validation if configured (UPS/FedEx/USPS/DHL — already built), (2) Nominatim/OSM — always available, free, worldwide, structured search with address components, (3) Free-form geocode fallback. Every WC3 installation gets verification + lat/lng out of the box. Lat/lng is critical for desktop-hosted local commerce proximity search ("products within 10 miles"). Updated `tasks.py` to route through supervisor.

- **Tax calc wired — ZIP-driven** — new `apps/transactions/services/tax_lookup.py`. ZIP code is primary input: ZIP → state (via `zip_to_state()` using built-in prefix range table or Setting `zip_to_state` from WC_HQ) → rate (via Setting `us_state_tax_rates` from WC_HQ or local TaxJurisdiction override). `customer_defaults.py` extracts ZIP from customer address, auto-populates `finance.sales_tax_rate`. `tax_service.py` builtin calc now reads TaxJurisdiction records instead of hard-coded state rates. `__init__` checks for `tax_service` Connection record before Django settings. Staged Connection record `conn-tax-service` in `seed_connections.py` for future Avalara/TaxJar/Vertex.

- **BOM cost rollup — 3 depth modes** — `recalc_parent_cost(item_id, depth=1|2|0)`. depth=1: kit (children's own costs). depth=2: explode one level of intermediates. depth=0: all levels to leaf nodes. Bill's insight: users may have intermediate subassemblies in stock — exploding all levels would consume raw materials they already have. Recursive `_rollup_cost()` checks if child has BOM and depth allows before exploding. Depth stored in `cost.components.depth`.

- **Pricing — margin warning, not enforcement** — changed `resolve_price()` to return `below_margin_floor` as a warning flag only. System never overrides user's price. WC2 heritage: `PriceBelowMargi` warned but never blocked.

- **Pricing — per-level quantity breaks** — `Item.price.qty_breaks` now supports per-level columns: `{"min_qty": 25, "retail": 11.00, "wholesale_pct": 33.3}`. Dollar price wins. Percentage calculates from break's base or item base. Updated both `resolve_unit_price()` and `resolve_price()`.

- **Pricing — catalog resolution** — `_resolve_catalog_price()` added to pricing chain as Step 0 (highest priority). Two modes: item-specific CatalogLine with fixed price/tiers, or universal % catalog (blanket discount on all products). Targeting via customer_orgbase FK, applies_to scope, or universal. Higher priority wins. Universal % applied after base price resolves from standard chain.

- **Early payment discount** — wired into `payment_pending.py` `_apply_one()`. Checks `finance.discount_days` and `finance.discount_rate` against payment date. Creates a separate Payment record (`payment_method='discount'`, ref `EPD-{invoice_id}`) — every dollar gets its own record, its own GL posting, its own audit trail. `finance.discount_taken` prevents double application.

- **Write-off difference** — `_write_off_balance()` in `payment_pending.py`. `apply_payment_to_invoice(write_off_difference=True)` creates a Payment record (`payment_method='write_off'`, ref `WO-{invoice_id}`) for any remaining balance. WC2 heritage: "Discount Difference" checkbox in Apply Payment dialog.

- **Returns = negative invoices** — decision: no separate RMA model. credit_note invoice type handles returns. Negative quantities, inventory reverses, GL reverses. Same conversion chain.

## Lessons for Allie

1. **WC2's data→information pattern is three layers** — line extension (extend each line), header rollup (sum lines into totals), cross-document consolidation (aggregate across invoices/payments into customer intelligence). WC3 already has all three — they just needed wiring. The architecture was right; the connections were missing. Domain: [WC3/Architecture]

2. **ZIP drives tax, not state** — user enters ZIP first. State is derived. Tax rate is looked up. No manual entry. The Setting from WC_HQ carries all 50 state rates. Local TaxJurisdiction records override when needed. Domain: [WC3/Tax]

3. **Every dollar gets its own Payment record** — cash, discounts, write-offs are all Payments with their own GL posting. No silent adjustments to totals. The audit trail is the Payment table, not metadata on the invoice. Domain: [WC3/Payments]

4. **Margin floor is a WARNING, not enforcement** — WC2 warned. WC3 should warn. The user is in control. The system that overrides the user's price is the system the user stops trusting. Domain: [WC3/Pricing]

5. **Lat/lng is not optional for desktop hosting** — proximity search ("products within 10 miles") requires every address to be geocoded. Nominatim is free and worldwide. No carrier account needed. This is what makes local commerce discoverable. Domain: [WC3/Architecture]

6. **BOM depth is an inventory decision** — depth=1 (kit) means subassemblies are stocked units. depth=0 (all) means cost from raw materials. The difference matters when you have intermediates on the shelf. Let the user choose. Domain: [WC3/Products]

7. **Alice and Allie confabulate without data** — both agents invented field paths and structures that don't exist in WC3. Allie recommended micro-services and BPMN engines. Alice invented dot-notation paths. Always review their vectors before posting. Feed them data first, ask narrow questions. Domain: [ALLIE/Process]
