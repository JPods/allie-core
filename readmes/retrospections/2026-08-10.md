## Key Decisions

- **No grace period on terms cut-off** — cut-off is the cut-off. WC2 overthought it.
- **Consignment skip is status-based** — `status='consigned'` skips journalize. Simple.
- **Hard delete for dedup** — junk does not grow better with age. Bundle file is temporary working space, not archive. Users work through it until it's gone.
- **Per-item campaign discount managed by catalogs** — DynamicCatalogs handles upstream pricing, not a separate WC3 pricing engine.
- **Reports as executable functions** — `category='function'` distinguishes executable reports from print/display. Selected from the report dialog, not buttons.
- **vendor_id only for split** — no manufacturer_id branching. If the manufacturer is the vendor, their vendor_id is used.
- **User decides product vs commission** — the system knows by item.vendor_id. If the item has a vendor, it's a commission line for that manufacturer.

## Lessons for Allie

1. **WC2 has 20 years of production business logic** — most of it is architecturally replaced (4D desktop → Django), but the domain algorithms (terms cut-off, FIFO depletion walk, commission scaling, reorder velocity) took decades to get right. Extract as specifications, build fresh in Python. [Cross-domain]

2. **Hard delete is correct for dedup** — the bundle file is the working space, not permanent storage. Users who want to keep data can back up before working. Soft-deleting duplicates just grows the junk pile. [WC3]

3. **Reports as functions** — the Report model with `category='function'` and `config.function_path` is the standard way to expose executable logic to users. Selected from the report dialog. Not buttons, not admin actions. This pattern will be used for many more functions. [WC3]

4. **The tradeshow split is a 3-step process** — split order by vendor, manufacturer fulfills, commission invoice after fulfillment. Not a one-click operation. Each step is a separate Report function. [WC3]

## Scars

- **AR aging task was silently dropping orgs** — `[:batch_size]` without pagination means orgs beyond 100 never get aged. Any batch task that uses `[:limit]` without a cursor loop has this bug. Check all Celery tasks for this pattern.
