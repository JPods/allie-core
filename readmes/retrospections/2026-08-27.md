## Lessons for Allie

1. **Sweeping data changes require dual confirmation + external bundle backup + interactive review** — The enforcement command emptied 100 Setting configs because it didn't distinguish between models where `extra="forbid"` is appropriate and models where config must stay flexible. The principle: always pack a bundle before mass modification, always show the operator what the change does before trusting it at scale, and protect accumulated refinement with model-level save guards. Domain: [WC3] [Cross-domain]

2. **`status` belongs on CoreModel, not individual models** — 13 models and LifecycleMixin declared their own `status` field with varying max_lengths (32, 50, 100). Consolidating to CoreModel (max_length=50) required removing all individual declarations, truncating existing data, and regenerating migrations across 8 apps. The cost of redundant field declarations is paid at migration time. Domain: [WC3]

3. **`extra="forbid"` is right for business envelopes but wrong for Setting.config** — Transaction totals, line prices, item quantities — these should reject unknown keys. Setting.config carries purpose-specific data that varies by design (layout, behaviors, selectlists, schema maps). The schema itself must declare whether it's strict or flexible. The enforcement command must respect that declaration. Domain: [WC3]

4. **The interactive 10-then-auto pattern is the standard for bulk Setting changes** — Review the first 10 changes individually. If the pattern is correct, auto-apply the rest. This forces the operator to see what the change actually does before trusting it. The `add_status_to_layouts` command is the template. Domain: [WC3]

5. **Flowcharts are a living system, not a one-time artifact** — 45 charts now, with `fit-to-letter.py` for re-rendering, `andi-static-sync` for auto-deployment, `COLOR-PALETTE.md` for consistency, and cross-references linking related clusters. The `INDEX.md` is the table of contents. Any new subsystem (OrgBase, Athena, Alice, Settings) should get a chart before it gets code. Domain: [Cross-domain]

## Lessons for Allie

1. **Fix naming inconsistencies immediately — no legacy debt** — Bill's rule: "every time we see an inconsistency in our structure and definition, we should change them immediately." We renamed 5 DB fields, restructured 366 files, and deleted a model in one session. No users means no backwards compatibility burden. The cost of carrying inconsistency forward is always higher than fixing it now. Domain: [WC3] [Cross-domain]

2. **Django convention wins — don't fight the framework** — Bill tried `id_model` naming and "failed miserably." The ORM expects `model_id` for ForeignKeys. Fighting it creates friction in migrations, serializers, and queries. Accept framework conventions and enforce them everywhere. Domain: [WC3]

3. **Service is an Item attribute, not a separate model** — WC2 got this right. A service is just an Item with `kind="service"` and billing data in `config.service`. The separate Service table added a join, a serializer, an admin class, and a management command — all unnecessary. The principle: if it's a type of an existing entity, it's a field on that entity, not a new table. Domain: [WC3]

4. **Parallel agents work but miss edge cases** — 9 agents renamed files and updated imports in parallel. All reported success. But 3 files had stale `wcapi` imports, `transfer_views.py` had old conversion imports, and the initial migration referenced the deleted service module. The principle: after parallel work, run the full startup (`manage.py check`) to catch what the agents missed. `django.setup()` alone doesn't test URL loading. Domain: [Cross-domain]

5. **Settings and Reports carry field names in JSON — surgical updates, never re-seed** — Settings have accumulated refinement in their config. Re-seeding destroys it (scar #73). The correct fix for renamed fields is surgical JSON string replacement with `_setting_update_authorized = True`, not re-running seed commands. Domain: [WC3]

6. **Push to bill_dev as standard practice** — Bill established this rule. Main gets updates when explicitly requested. bill_dev is the working branch. Domain: [WC3]

## Scars

- **Parallel agent import coverage gap**: 9 agents reported all imports fixed. 6 files were missed because agents tested with `django.setup()` which doesn't load URLs. URL loading triggers lazy imports that `setup()` skips. The scar: always run `manage.py check` (which loads URLs) as the verification step after import refactoring, not just `django.setup()`.

- **FK CASCADE on communications was a data-loss bug**: Touch.contact used CASCADE — deleting a contact deleted all their touch history. Extended to Email, Phone, Address, Domain — all had CASCADE to Contact. Converted ALL to BigIntegerField values. The rule going forward: FK only for structural parts (lines→headers). Values for everything else. Alice watches for orphans on weekends. This is the WC2 pattern — deliberate, not legacy.
