## Lessons for Allie

1. **ida replaces account_number — one field, two jobs** — The 4-digit prefix sorts correctly; the CamelCase suffix tells non-accountants what it is. No redundant fields. This is the pattern for all identifier consolidation. Domain tag: [WC3]

2. **Three-tier database architecture is the Desktop Hosting foundation** — System (settings, reports, GL, terms), Demo (curated training data), FreshStart (empty). Every seed command must be idempotent. `seed_freshstart` chains them all. A new company runs one command and is ready. Domain tag: [WC3]

3. **Select lists belong in field_access, not in a separate table** — WC2 had popup/popupchoices (two tables, FK lookup). WC3 puts choices inline in the Setting that already governs the model's field behavior. One JSON key, already cached, already synced. The `allow_custom` flag replaces WC2's `Alternates`. Domain tag: [WC3]

4. **Specs repo needs two distribution channels** — Git (source of truth, version controlled, Gordy can PR) and Google Docs (read-only for non-git people). The repo is authoritative; Drive gets exports. Never fork the content. Domain tag: [Cross-domain]

5. **Settings, actions, and reports are sacred during data replacement** — Bill explicitly stated these three survive any database rebuild. Everything else (contacts, items, transactions, Faker noise) can be replaced. This is the rule for all three database tiers. Domain tag: [WC3]
